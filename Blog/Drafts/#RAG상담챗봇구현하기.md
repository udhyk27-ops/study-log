RAG 상담 챗봇 구현하면서 겪은 문제와 해결

학교 과제로 FAQ 데이터를 활용한 RAG 상담 챗봇을 구현했다.

처음에는 사용자의 질문을 그대로 OpenAI API에 전달하면 답변할 수 있을 것이라고 생각했지만, 이렇게 하면 내가 가진 FAQ 데이터를 기반으로 답변한다는 보장이 없었다.

그래서 질문과 관련된 문서를 먼저 검색하고, 검색된 내용을 LLM에게 전달하는 RAG 구조로 구현했다.

검색 결과가 원하는 내용을 찾지 못하는 문제

처음에는 FAQ 데이터를 그대로 임베딩해서 검색했는데, 질문의 표현이 FAQ 문장과 조금만 달라도 원하는 데이터가 제대로 검색되지 않는 경우가 있었다.

이를 해결하기 위해 FAQ 데이터를 적절한 단위로 나누고, 질문과 답변 내용을 함께 검색할 수 있도록 데이터 구조를 정리했다.

이후 사용자의 질문을 embedding으로 변환하고, 유사한 FAQ를 검색한 뒤 검색 결과를 프롬프트에 포함해 답변하도록 구성했다.

환경 설정 문제

API Key를 코드에 직접 작성하지 않고 .env 파일에서 관리하도록 구성했다.

또한 프로젝트 제출 시에는 .env와 .venv, __pycache__ 등을 제외하고 필요한 소스 코드와 requirements.txt만 정리했다.

마무리

이번 프로젝트를 진행하면서 RAG의 핵심은 단순히 LLM API를 호출하는 것이 아니라,

질문 → 검색 → 관련 문서 → LLM 답변

이라는 흐름을 얼마나 안정적으로 구성하느냐에 있다는 것을 알게 됐다.

특히 검색 결과가 좋지 않으면 아무리 좋은 LLM을 사용해도 원하는 답변을 얻기 어렵다는 점이 인상적이었다.

# 자바 코딩테스트 벼락치기 가이드 (손코딩 대비)

## 0. 원본 20단계 계획에 대한 평가

원본 계획은 문법 나열식이라 벼락치기에는 비효율적이다. 시험에 실제로 나오는 건 "문법 지식"이 아니라 "자료구조 선택 + 구현 정확도"다. 다음 기준으로 정리했다.

- **버릴 것**: 메서드 오버로딩, 형변환의 디테일한 규칙, switch문의 신문법(화살표식 등), Math 함수 완전정복, Scanner의 모든 메서드 암기 — 실전에서 거의 안 나오거나 나와도 감점 요인이 아님
- **줄일 것**: 배열 복사 방식(Arrays.copyOf 정도만)
- **추가할 것**: `BufferedReader + StringTokenizer` (Scanner보다 빠르고 실무/기출 모두에서 자주 요구), 람다식 Comparator, 시간복잡도 감으로 자료구조 고르는 판단 기준
- **DP/그래프는 얕게**: 벼락치기 기간에 DP 이론을 파는 건 투자 대비 효율이 낮다. 프로그래머스 레벨2 수준의 패턴(1차원 DP, 간단한 그래프 탐색)만 손에 익히는 걸 목표로 한다.

아래는 이 기준으로 재구성한 4단계 커리큘럼이다.

## 1단계: 입출력 + 기본 문법 (1일차)

### 코드 골격 (고정 패턴, 통암기)
```java
import java.util.*;
import java.io.*;

public class Solution {
    public static void main(String[] args) throws IOException {
        // 코드
    }
}
```
프로그래머스는 `class Solution { public int solution(int[] arr) {...} }` 형태로 메서드만 채우면 됨 (main 불필요). **백준/기업 자체 코테는 직접 입출력을 짜야 함** — 시험 전에 어떤 방식인지 반드시 확인.

### 입출력 방식 종류
입력엔 Scanner, BufferedReader(+StringTokenizer) 두 가지가 주로 쓰이고, 출력이 많을 땐 StringBuilder에 모았다가 한 번에 출력하는 방식을 쓴다. 각각의 사용법과 메서드는 아래에서 정리한다.

### Scanner 사용법 + 메서드

기본 사용 문법:
```java
Scanner sc = new Scanner(System.in);
int n = sc.nextInt();
String s = sc.next();
sc.close(); // 안 닫아도 채점엔 보통 지장 없지만 습관적으로 넣는 게 안전
```

Scanner는 **공백(스페이스, 탭, 줄바꿈)을 기준으로 토큰을 나눠서 읽는다.** `nextInt()`, `next()` 등은 공백 전까지만 한 번에 읽으므로, `10 20`처럼 값이 여러 개면 각각 따로 호출해야 한다.

| 메서드 | 한 줄 설명 |
|---|---|
| `nextInt()` | 공백 기준으로 정수 하나 읽기 |
| `nextLong()` | 공백 기준으로 long 하나 읽기 (int 범위 넘을 때) |
| `nextDouble()` | 공백 기준으로 실수 하나 읽기 |
| `next()` | 공백 기준으로 문자열(단어) 하나 읽기 |
| `nextLine()` | 공백 포함, 줄바꿈 전까지 한 줄 전체 읽기 |
| `hasNext()` / `hasNextInt()` | 다음 입력이 더 있는지 확인 (입력 개수 모를 때 반복 조건으로 사용) |

**자주 나는 실수**: `nextInt()`(또는 `next()`) 뒤에 바로 `nextLine()`을 쓰면, 앞에서 숫자만 읽고 남겨둔 개행문자(`\n`)를 `nextLine()`이 그대로 읽어버려서 빈 문자열이 나온다.
```java
int n = sc.nextInt();
String s = sc.nextLine(); // 의도와 다르게 빈 줄이 읽힘
```
해결: 중간에 `sc.nextLine()`을 한 번 더 넣어 남은 개행문자를 버리거나, 처음부터 `nextLine()`으로 한 줄을 통째로 받은 뒤 직접 split해서 파싱한다.

### BufferedReader 사용법 + 메서드

기본 사용 문법:
```java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
String line = br.readLine();       // 한 줄 통째로 읽기 (공백 포함, 개행 전까지)
int n = Integer.parseInt(line);    // 문자열이라 직접 형변환 필요
br.close();
```
main 메서드에 `throws IOException`을 붙여야 컴파일 에러가 안 남 (readLine()이 체크 예외를 던짐).

| 메서드 | 한 줄 설명 |
|---|---|
| `readLine()` | 한 줄 전체를 문자열로 읽기 (공백 포함). 더 읽을 줄이 없으면 null 반환 |
| `close()` | 스트림 닫기 (안 닫아도 채점엔 보통 지장 없음) |

BufferedReader는 **문자열만** 읽기 때문에, 정수나 여러 값을 나눠 받으려면 `Integer.parseInt()`와 `StringTokenizer`(또는 `split()`)를 같이 써야 한다.

| 메서드 (StringTokenizer) | 한 줄 설명 |
|---|---|
| `new StringTokenizer(line)` | 한 줄 문자열을 공백 기준으로 쪼갤 준비 |
| `nextToken()` | 쪼갠 토큰을 하나씩 순서대로 꺼내기 |
| `hasMoreTokens()` | 꺼낼 토큰이 더 있는지 확인 |
| `countTokens()` | 남은 토큰 개수 확인 |

한 줄에 여러 값 받는 예시 (N, M 두 값):
```java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
StringTokenizer st = new StringTokenizer(br.readLine());
int n = Integer.parseInt(st.nextToken());
int m = Integer.parseInt(st.nextToken());
```

### 언제 Scanner, 언제 BufferedReader

| 상황 | 선택 |
|---|---|
| 프로그래머스 스타일 (매개변수로 입력 주어짐) | 둘 다 불필요 — 입출력 직접 안 짜도 됨 |
| 입력량 적고 빠르게 짜고 싶을 때 | Scanner |
| 입력량 많거나(반복문으로 N줄 이상) 속도가 중요할 때 | BufferedReader + StringTokenizer |
| 손코딩 시험에서 어떤 걸 써야 할지 모를 때 | BufferedReader가 더 범용적이고 실수도 적어서 기본값으로 추천 |

### 출력 관련

| 방식 | 한 줄 설명 |
|---|---|
| `System.out.println(x)` | 값 출력 후 줄바꿈 |
| `System.out.print(x)` | 값만 출력, 줄바꿈 없음 |
| `System.out.printf("%d %.2f%n", n, d)` | 형식 지정 출력 (자릿수, 소수점 등 맞출 때) |
| `StringBuilder` + 마지막에 한 번에 출력 | 출력을 반복문 안에서 여러 번 해야 할 때, println 반복보다 빠름 (`sb.append(x).append("\n")` 후 `System.out.print(sb)`) |

### 형변환 (문자열 ↔ 숫자)

| 상황 | 코드 |
|---|---|
| 문자열 → 정수 | `Integer.parseInt(str)` |
| 문자열 → long | `Long.parseLong(str)` |
| 정수 → 문자열 | `String.valueOf(n)` 또는 `n + ""` |

### 입력 개수를 모를 때 (자주 나오는 실수 포인트)

| 상황 | 코드 |
|---|---|
| 몇 줄 들어올지 모를 때 (EOF까지 읽기) | `String line; while ((line = br.readLine()) != null) { ... }` |
| Scanner로 값이 더 있는지 확인 | `while (sc.hasNextInt()) { int x = sc.nextInt(); }` |
| 정해진 줄 수(n)만큼 반복 입력 | `for (int i = 0; i < n; i++) { st = new StringTokenizer(br.readLine()); ... }` — 한 줄 읽을 때마다 StringTokenizer를 새로 만들어야 함 (재사용 X) |

### 문자열 파싱 심화

| 상황 | 코드 | 주의점 |
|---|---|---|
| 공백으로 구분된 값들을 한 줄로 받아 정수 배열로 변환 | `int[] arr = Arrays.stream(br.readLine().split(" ")).mapToInt(Integer::parseInt).toArray();` | 프로그래머스보다 백준류 손코딩에서 자주 나오는 패턴, 통으로 외워두면 편함 |
| 특수문자로 split | `str.split("\\.")` (마침표), `str.split("\\|")` (파이프) | `.`, `|`, `+` 등은 정규식 특수문자라 그냥 쓰면 에러 나거나 의도와 다르게 동작 — 반드시 `\\`로 이스케이프 |
| 공백이 여러 개 섞여 있을 때 | `str.split(" +")` 또는 `str.trim().split("\\s+")` | 공백 하나만 기준으로 split하면 빈 문자열(`""`)이 배열에 섞여 들어가는 함정 있음 |
| 문자 하나씩 숫자로 변환 | `ch - '0'` | 문자 `'5'`를 정수 `5`로 바꿀 때 자주 쓰는 트릭 (아스키 코드 차 이용) |

### 코딩테스트에서 알아야 할 기초 문법 체크리스트

| 항목 | 알아야 할 정도 |
|---|---|
| `public / private / static` | static만 확실히 (메서드/변수 앞에 왜 붙는지). private은 실전에서 거의 안 씀 |
| `void`, `return` | 값 반환 없으면 void, 있으면 타입 명시 후 return — 이것만 |
| 형변환 세부 규칙 | 암기 불필요, `(int)`, `(double)` 캐스팅 정도만 |
| switch문 | 옛날 방식(`case X: ... break;`)만. 신문법(`case X ->`)은 몰라도 됨 |
| 메서드 오버로딩 | 벼락치기 범위 아님, 생략 |
| 향상된 for문 (for-each) | `for (int x : arr)` 형태. 배열/리스트를 인덱스 없이 순회할 때 코드가 짧아져 실전에서 가장 많이 씀. 단, 인덱스가 필요한 순간(위치 비교 등)엔 기존 for문 사용 |
| 삼항연산자 | `조건 ? 참일때값 : 거짓일때값`. 짧은 if-else를 한 줄로 줄일 때 자주 씀 (예: `max = a > b ? a : b;`) |
| 레이블(label) | 중첩 반복문 조기 종료 시 필수. flag 변수로 지저분하게 짜지 않으려면 알아둘 것: |

```java
outer:
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        if (조건) break outer;
    }
}
```

## 2단계: 배열·문자열·자료구조 (2일차)

### 배열
- 2차원 배열 선언/순회, `arr.length` (배열은 `.length`, 문자열은 `.length()` — 실수 자주 나는 부분)
- 배열 복사는 `Arrays.copyOf(arr, n)` 하나만 알면 됨

### 배열 ↔ 문자열 변환 (실전에서 정말 많이 씀)

| 변환 방향 | 코드 | 언제 쓰는지 |
|---|---|---|
| 문자열 → 문자 배열 | `char[] c = str.toCharArray();` | 문자 단위로 정렬/비교해야 할 때 (아나그램, 팰린드롬) |
| 문자열 → 문자열 배열 | `String[] arr = str.split(" ");` | 구분자로 나눠서 여러 값을 각각 다룰 때 |
| 문자열 → 정수 배열 | `int[] arr = Arrays.stream(str.split(" ")).mapToInt(Integer::parseInt).toArray();` | 공백/쉼표로 구분된 숫자들을 한 번에 정수 배열로 바꿀 때 |
| 문자 배열 → 문자열 | `String s = new String(charArr);` 또는 `String s = String.valueOf(charArr);` | toCharArray()로 가공한 걸 다시 문자열로 합칠 때 |
| 정수 배열 → 문자열 (합치기) | `String s = Arrays.toString(arr);` (디버깅용, `[1, 2, 3]` 형태) 또는 `StringBuilder`로 직접 이어붙이기 (원하는 형식 만들 때) | 결과를 특정 형식으로 출력해야 할 때는 StringBuilder가 안전 |
| 리스트 → 문자열 (구분자 지정) | `String s = String.join(",", list);` | 리스트를 특정 구분자로 합쳐서 출력할 때 |
| 문자열 배열 → 리스트 | `List<String> list = Arrays.asList(arr);` | split 결과를 리스트로 다루고 싶을 때 (단, 크기 고정이라 add/remove 불가 — 필요하면 `new ArrayList<>(Arrays.asList(arr))`) |
| 2차원 배열 → 문자열 (디버깅) | `Arrays.deepToString(arr2d)` | 2차원 배열 값 확인용, 결과 출력엔 잘 안 씀 |

`Arrays.toString()`류는 디버깅/확인용으로는 편하지만, 문제에서 요구하는 출력 형식(공백 구분, 특정 기호 등)에 맞추려면 대부분 StringBuilder로 직접 조립하는 게 안전하다.

### String 메서드 — 시험 최다 출제 파트

| 메서드 | 언제 쓰는지 |
|---|---|
| `length()` | 문자열 길이 확인 (반복문 범위 등) |
| `charAt(i)` | i번째 문자 하나 꺼낼 때 |
| `substring(s, e)` | 부분 문자열 자를 때. e는 미포함이라 인덱스 계산 시 주의 |
| `split(regex)` | 특정 구분자로 여러 조각 나눌 때 (예: 공백, 쉼표로 분리) |
| `equals(str)` | 문자열 값 비교 (`==`는 주소 비교라 쓰면 안 됨) |
| `equalsIgnoreCase(str)` | 대소문자 무시하고 값 비교 |
| `contains(str)` | 특정 문자열이 포함되어 있는지 확인 |
| `startsWith(str)` / `endsWith(str)` | 특정 문자열로 시작/끝나는지 확인 (접두사/접미사 판별) |
| `replace(a, b)` | 특정 문자(열)를 다른 문자(열)로 치환 |
| `toUpperCase()` / `toLowerCase()` | 대소문자 통일해서 비교할 때 |
| `trim()` | 앞뒤 공백 제거 (입력값 정제) |
| `toCharArray()` | 문자 단위로 하나씩 순회/정렬해야 할 때 (예: 아나그램 체크) |
| `String.join(구분자, 배열/리스트)` | 배열이나 리스트를 문자열로 합칠 때 |
| `indexOf(str)` | 특정 문자(열)가 처음 나오는 위치 찾기 (없으면 -1) |

문자열은 불변(immutable) 객체라 반복적으로 이어붙이면 매번 새 객체가 생겨 느려짐 → 이럴 땐 StringBuilder 사용.

### StringBuilder 메서드 (문자열 조립에 자주 쓰이니 전부 익혀둘 것)

| 메서드 | 언제 쓰는지 |
|---|---|
| `append(x)` | 문자열/문자/숫자를 뒤에 이어붙일 때 (반복 이어붙이기 최적화, 가장 많이 씀) |
| `toString()` | 최종 결과를 String으로 변환해서 반환할 때 |
| `reverse()` | 문자열을 뒤집을 때 (팰린드롬 검사, 뒤집기 문제) |
| `insert(idx, x)` | 특정 위치에 값을 끼워넣을 때 |
| `deleteCharAt(idx)` | 특정 위치의 문자 하나 삭제할 때 |
| `delete(s, e)` | 특정 구간(s~e-1)의 문자들을 한 번에 삭제할 때 |
| `setCharAt(idx, c)` | 특정 위치의 문자를 바꿀 때 |
| `charAt(idx)` | 조립 중인 문자열에서 특정 위치의 문자 확인 |
| `length()` | 현재까지 조립된 길이 확인 (마지막 문자 지우기 전 위치 계산 등에 사용) |
| `replace(s, e, str)` | 특정 구간(s~e-1)을 다른 문자열로 통째로 교체할 때 |
| `indexOf(str)` | 조립된 문자열 안에서 특정 문자열 위치 찾기 |

자주 쓰는 조합: 마지막에 불필요하게 붙은 구분자 지우기 → `sb.deleteCharAt(sb.length() - 1)`.

### ArrayList 메서드

| 메서드 | 언제 쓰는지 |
|---|---|
| `add(x)` | 값 추가 (크기 가변적일 때 배열 대신 사용) |
| `get(i)` | i번째 값 조회 |
| `set(i, x)` | i번째 값 변경 |
| `remove(i)` / `remove(Object)` | 인덱스 또는 값으로 삭제 (인덱스가 int면 인덱스 삭제, Integer 객체면 값 삭제 — 오토박싱 함정 주의) |
| `size()` | 현재 크기 확인 (배열의 `.length`에 대응) |
| `contains(x)` | 특정 값 포함 여부 확인 |
| `indexOf(x)` | 특정 값의 위치 찾기 |

배열은 크기 고정, 삽입/삭제가 없을 때. ArrayList는 크기 가변적이거나 삽입/삭제가 잦을 때 선택. 2차원 리스트 `List<List<Integer>>` 선언법은 그래프 인접리스트 구현에 필수라 손에 익혀둘 것.

### HashMap 메서드

| 메서드 | 언제 쓰는지 |
|---|---|
| `put(key, value)` | 값 저장/갱신 |
| `get(key)` | 키로 값 조회 (없으면 null) |
| `getOrDefault(key, 기본값)` | 키가 없을 때 기본값 반환 — 빈도수 계산에 필수 |
| `containsKey(key)` | 특정 키가 있는지 확인 |
| `remove(key)` | 키-값 삭제 |
| `keySet()` | 모든 키를 순회하고 싶을 때 |
| `entrySet()` | 키와 값을 동시에 순회하고 싶을 때 |

빈도수 계산 패턴 (통암기):
```java
Map<String, Integer> map = new HashMap<>();
map.put(key, map.getOrDefault(key, 0) + 1);
```
"가장 많이 등장한 문자", "완주하지 못한 선수" 류 문제 대부분 이 패턴 하나로 해결.

### HashSet 메서드

| 메서드 | 언제 쓰는지 |
|---|---|
| `add(x)` | 값 추가 (이미 있으면 무시됨 → 중복 자동 제거) |
| `contains(x)` | 값이 있는지 확인 (방문 체크, 중복 체크) |
| `remove(x)` | 값 삭제 |
| `size()` | 개수 확인 |

중복 제거가 필요하거나 "이미 나온 값인지"만 빠르게 확인하면 될 때 HashMap 대신 HashSet 사용.

### Stack / Queue

| 자료형 | 주요 메서드 | 언제 쓰는지 |
|---|---|---|
| Stack | `push(x)`, `pop()`, `peek()` | 괄호 짝 맞추기, 최근에 넣은 것부터 꺼내야 할 때 |
| Queue (`LinkedList` 구현) | `offer(x)`, `poll()`, `peek()` | 먼저 들어온 것부터 처리 (BFS 필수) |

Deque, PriorityQueue는 기초 코딩테스트에서 잘 안 나오니 벼락치기 범위에서는 생략. Stack/Queue 두 개만 손에 익혀도 충분.

## 3단계: 정렬 + 기본 알고리즘 패턴 (3일차)

### 정렬
```java
Arrays.sort(arr); // 배열, 오름차순 고정 (기본형은 내림차순 직접 불가 → Integer[]로 박싱 필요)
Collections.sort(list, (a, b) -> a - b); // 오름차순
Collections.sort(list, (a, b) -> b - a); // 내림차순
```
- 커스텀 정렬(예: 문자열 길이순, 두 값 합산 기준)은 람다식 Comparator로 짜는 연습이 실전에서 제일 많이 씀
- 기본형 배열 내림차순 정렬: `Arrays.sort` 후 뒤집거나, Integer 박싱해서 Comparator 사용 — 이 함정 꼭 기억할 것

### 자주 나오는 알고리즘 패턴 (프로그래머스 기준)
| 패턴 | 언제 쓰는지 | 대표 유형 |
|---|---|---|
| 완전탐색 | 데이터 크기 작을 때(N≤10~15) 모든 경우 확인 | 숫자 야구, 카펫 |
| 해시(HashMap) | 빈도수, 매칭 여부 확인 | 완주하지 못한 선수, 위장 |
| 투 포인터 | 정렬된 배열에서 두 지점을 좁혀갈 때 | 두 수의 합, 구명보트 |
| 슬라이딩 윈도우 | 연속 구간의 합/최댓값 구할 때 | 최댓값 부분합 |
| 누적합 | 구간 합을 반복 계산해야 할 때 | 구간 합 구하기 |
| 이진 탐색 | 정렬된 데이터에서 값 찾기, 파라메트릭 서치 | 입국심사, 징검다리 |

이 표의 패턴 이름만 보고 "아, 이건 투 포인터네" 라고 즉시 떠올릴 수 있는 게 목표. 코드는 3~4줄 스켈레톤만 외워두면 됨.

## 4단계: 심화 알고리즘 — 얕고 넓게 (4일차)

벼락치기 범위에서는 이론보다 "이 문제는 어떤 방식으로 접근하면 되는지" 감만 잡으면 충분하다.

| 알고리즘 | 한 줄 설명 | 언제 쓰는지 |
|---|---|---|
| 재귀 | 함수가 자기 자신을 다시 호출 | 문제를 더 작은 같은 문제로 쪼갤 수 있을 때 (DFS, DP의 기반) |
| DFS | 한 방향으로 끝까지 갔다가 막히면 되돌아옴 | 모든 경로/조합을 다 확인해야 할 때, 그래프·미로 탐색 |
| BFS | 가까운 것부터 순서대로 넓게 퍼짐 | 최단 거리, 최소 횟수를 구할 때 |
| 백트래킹 | DFS 하다가 조건 안 맞으면 그 이전 상태로 되돌아감 | 순열/조합/모든 경우의 수 중 조건에 맞는 것만 찾을 때 |
| 그리디 | 매 순간 지금 봤을 때 제일 좋은 선택을 함 | 정렬 후 앞에서부터 처리해도 최적해가 나올 때 |
| DP | 한 번 계산한 결과를 저장해서 재사용 | 같은 계산이 반복될 때 (피보나치, 계단 오르기류) |

DFS/BFS 기본 골격 (이 두 개만 손으로 3번 이상 써볼 것):
```java
// DFS
void dfs(int node, boolean[] visited) {
    visited[node] = true;
    for (int next : graph.get(node)) {
        if (!visited[next]) dfs(next, visited);
    }
}

// BFS
void bfs(int start, boolean[] visited) {
    Queue<Integer> queue = new LinkedList<>();
    queue.offer(start);
    visited[start] = true;
    while (!queue.isEmpty()) {
        int cur = queue.poll();
        for (int next : graph.get(cur)) {
            if (!visited[next]) {
                visited[next] = true;
                queue.offer(next);
            }
        }
    }
}
```

DP는 1차원(피보나치, 계단 오르기 변형)까지만 확실히 해두면 충분. 2차원 DP나 복잡한 그래프 이론(다익스트라 등)은 벼락치기 범위 밖이니 시간 남을 때만.

## 5단계: 문제 풀이 프로세스 (실전 체크리스트)

면접/시험장에서 이 순서를 그대로 따라가는 게 중요:

1. 입출력 형식부터 확인 (매개변수인지, 직접 입력받는지)
2. 제한사항 확인 → N의 범위로 시간복잡도 역산 (N≤1000이면 O(N²)도 가능, N≤100000이면 O(N log N) 이하 필요)
3. 예제를 손으로 직접 따라가며 규칙 파악
4. 자료구조 먼저 결정 (배열/리스트/맵/셋/큐 중 뭐가 맞는지)
5. 코드 작성 후 예제 입력으로 직접 트레이싱 (컴파일 안 되므로 눈으로 실행)
6. 예외 케이스 점검: 빈 입력, 길이 1, 중복 값, 경계값

## 6단계: 손코딩 실전 대비

- IDE 자동완성이 없으므로 **import 목록, 클래스명 철자, 괄호 짝**을 정확히 아는 게 관건. 자주 쓰는 import는 통으로 외워라: `java.util.*`, `java.io.*`
- 세미콜론, 중괄호 짝을 셀 때 들여쓰기를 정확히 맞춰 쓰는 습관을 들일 것 (눈으로 검증하는 유일한 방법)
- 변수명은 짧고 일관되게(i, j, n, arr, map 등) — 손코딩 속도에 영향
- 컴파일러가 없으므로 오타가 나도 못 잡는다. 특히 `=`과 `==`, `length`와 `length()` 혼동을 스스로 점검하는 습관이 필요
- 시간이 없으면 완벽한 코드보다 "논리적으로 맞는 의사코드 수준의 자바 코드"를 우선 완성하고, 남는 시간에 문법을 다듬는 전략이 낫다

## 7단계: 프로그래머스 레벨 0~2 출제 경향과 대비 전략

### 레벨별 특징

| 레벨 | 특징 | 주로 나오는 유형 | 대비 포인트 |
|---|---|---|---|
| 레벨 0 | 입문, 문법 연습 수준 | 조건문, 반복문, 배열/문자열 기본 조작 | 1~2단계 개념만 확실하면 다 풀림. 시간 오래 걸리면 오히려 위험 신호 |
| 레벨 1 | 기초 구현 문제 | 조건문·반복문·문자열 처리, 기본 해시, 기본 정렬 | 구현만 되면 통과하는 난이도. 예외처리/출력 형식 실수만 조심하면 됨 |
| 레벨 2 | 실전형 구현 + 기본 알고리즘 | 해시, 스택/큐, 정렬, 완전탐색, 그리디, 기본 DFS/BFS | 기업 코딩테스트의 60~70%가 이 구간에서 출제됨. 벼락치기 목표는 여기까지 안정적으로 푸는 것 |

레벨 3 이상(DP 심화, 그래프 최적화, 자료구조 응용)은 벼락치기 범위를 벗어나므로 이 가이드에서는 다루지 않는다.

### 레벨 0 — 문법 익히기용

| 문제 | 필요한 개념 |
|---|---|
| 짝수는 싫어요 | 반복문, 조건문 |
| 배열 뒤집기 | 배열, Collections.reverse 또는 직접 순회 |
| 문자열 뒤집기 | StringBuilder.reverse() |
| 자릿수 더하기 | 정수를 문자열로 바꿔 순회 or % 연산 |
| 대문자와 소문자 | toCharArray, Character.isUpperCase |
| 없는 숫자 더하기 | 배열, HashSet 또는 합 계산 |
| 문자열 곱하기 | StringBuilder 반복 append |
| 최댓값 만들기 | 정렬 |

레벨 0은 개념 하나당 문제 하나가 매칭되는 구조라, 위 표를 다 풀어보면 1~2단계 내용이 저절로 손에 익는다.

### 레벨 1 — 구현 + 기초 해시/정렬

| 문제 | 필요한 개념 |
|---|---|
| 완주하지 못한 선수 | HashMap 빈도수 |
| 두 개 뽑아서 더하기 | 완전탐색 + HashSet(중복 제거) |
| 숫자 문자열과 영단어 | 문자열 파싱, replace |
| 크레인 인형뽑기 게임 | Stack |
| 실패율 | 정렬 + HashMap |
| 신규 아이디 추천 | 문자열 처리(정규식 없이 직접 필터링) |
| 시저 암호 | 문자 하나씩 순회 + 아스키 계산 |
| K번째수 | 배열 자르기 + 정렬 |
| 폰켓몬 | HashSet(중복 제거 후 개수) |
| 예산 | 정렬 + 완전탐색(누적) |

레벨 1은 "구현만 정확히 하면 통과"하는 난이도이므로, 표에서 다루는 String/HashMap 메서드가 실제로 손에서 바로 나오는지가 관건이다.

### 레벨 2 — 실전 알고리즘 패턴 적용

| 문제 | 필요한 개념 |
|---|---|
| 위장 | HashMap + 조합 계산(경우의 수 곱) |
| 구명보트 | 정렬 + 그리디(투 포인터) |
| 프린터 | Queue |
| 타겟 넘버 | DFS/백트래킹 |
| 네트워크 | DFS/BFS |
| 카펫 | 완전탐색 |
| 짝지어 제거하기 | Stack |
| 큰 수 만들기 | 그리디 |
| 게임 맵 최단거리 | BFS |
| 올바른 괄호 | Stack |
| 주식 가격 | 스택 또는 이중 반복문 |
| 기능개발 | Queue 또는 배열 시뮬레이션 |
| 전화번호 목록 | 정렬 + 문자열 startsWith |
| 피보나치 수 | 1차원 DP |

레벨 2는 "이 문제 = 이 패턴"이 바로 매칭돼야 시간 안에 풀린다. 3단계 알고리즘 패턴표, 4단계 DFS/BFS 골격 코드를 이 문제들에 그대로 적용해보는 연습이 벼락치기 마지막 단계로 가장 효율적이다.

### 벼락치기 학습 순서 제안
1. 레벨 0을 빠르게 전부 풀며 문법 감 잡기 (하루 이내로 끝내는 게 목표, 오래 걸리면 1~2단계 재복습)
2. 레벨 1을 풀며 String/HashMap 메서드가 실제로 손에서 나오는지 확인
3. 레벨 2를 풀며 패턴표와 매칭하는 연습 — 못 풀면 어떤 패턴인지부터 맞혀보고, 안 떠오르면 3~4단계 표로 돌아가서 복습
4. 시간이 남으면 같은 문제를 손코딩(에디터 없이 종이/메모장)으로 다시 풀어보며 실전 감각 점검

이 순서로 하루 3~5문제씩 풀면서, 풀 때마다 5단계 "문제 해결 프로세스" 체크리스트를 그대로 적용해보는 걸 권장한다.
